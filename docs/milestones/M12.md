## 2. 对原始计划的前提修正

1. **"纯前端接线" 不成立** → 实为两步：①前端 `PermissionCodes.cs` 先对齐后端 `IdentityConstants`（补 dashboard/agent/theme:edit/publish/metadata:edit/scan 常量）；②按钮级 `<PermissionGuard Require=…>` 包裹。
2. **P0-UI-08 置顶** → 它是唯一"直接 URL 绕过菜单权限"的真实安全缺陷，其余为体验问题，排 P0 第一。
3. **`component:*` 是新增域** → 不能只改前端；需同步后端 `IdentityConstants` + 前端 `PermissionCodes` + 种子（归 M12 扩展项，默认 P2）。
4. **P1-04（Test Connection）修正** → 后端已能对**已保存**数据源 `TestConnection(id)`；缺口是：前端新建态仍 Toast、且无"按连接串预测试"端点。方案二选一：A) 先保存再调 `TestConnection(id)`；B) 新增 `TestConnectionString(connStr)` 端点。

## 6. 统一规则与验收标准

- **四层权限贯穿**：`AuthGuard` → Page Permission → Action Permission → API Permission。
- 无权限用户**不看到按钮**（而非点击 403）。
- Viewer / Member / TenantAdmin 三角色端到端体验正常。
- 全量单测绿 + 三端 build 0 error + Golden 18/18 不变。
- `ResourceKeyRegistryTests` 等 i18n 护栏全绿（M3 已 ✅）。

## 7. 红线

- 不改动后端权限模型（已在 `IdentityConstants` 完整定义），M12 仅前端同步 + 包裹。
- `component:*` 为新增域，须同步后端 `IdentityConstants` + 前端 `PermissionCodes` + 种子（默认 P2，不阻塞 P0）。
- 不得引入新占位 / 假数据；M12-09/10/12 的 Toast 占位必须被真实调用替换。

> **修复（已落源码 + CI 复跑全绿）**：① `.github/workflows/dotnet-build.yml`「启动 Web API」步骤注入 `RateLimit__LoginLimit=500`/`RateLimit__GlobalLimit=1000`（与 Local 配置等价，仅 CI）；② `ThemeEditor.razor` 将 `_tokens` 防御性初始化为 `TokenOrder.ToDictionary(k=>k,"")`，并仿 `AppPreview`/`AppRun` 在 `OnInitialized` 订阅 `State.SessionRestoredChanged`、`OnAfterRenderAsync` 仅 `State.SessionRestored` 后取数；③ 测试侧 `WaitForLoadStateAsync(NetworkIdle)` 时序解耦保留。CI run 34568568564（commit 86a2245）= **16 通过 / 1 跳过 / 0 失败**，全绿。
