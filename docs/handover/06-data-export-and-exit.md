# 06 · 数据导出与退出流程

> 受众：**[双方]**｜所属：M14-07 交接包｜状态：**草稿**

> M14-07 验收判据 3：**退出可导出约定数据，数据保留与删除流程明确且有授权记录**。

---

## 1. 退出流程总览

```
① 提出退出申请（书面）
      ↓
② 授权确认（客户方有权人签字/工单审批）→ 形成授权记录
      ↓
③ 数据导出（按 §2 通道，交付「约定数据」）
      ↓
④ 服务停用（PATCH api/tenant-management/{id}/disable）
      ↓
⑤ 保留期届满 → 物理删除（DBA 执行）→ 删除记录归档
```

**原则**：先导出、后停用、再删除；每一步留痕。

## 2. 数据导出（按数据类型）

| # | 数据 | 导出通道 | 说明 |
|---|---|---|---|
| 1 | **元数据/业务数据**（租户、用户、权限、审计、业务语义、看板、应用定义） | SQL Server 原生导出：库级 `BACKUP`，或按表 `bcp` / `SELECT ... INTO` / 导出 CSV | 建议提供**按租户过滤**的导出脚本，避免带出他人数据 |
| 2 | **向量数据** | Qdrant 快照（REST `POST /collections/superbi_metadata/snapshots`）→ 下载快照文件 | 快照为二进制；如需可读格式，需另做「点 → JSONL」导出 |
| 3 | **配置与语义基线** | `appsettings*.json`（**脱敏**）、`scripts/schema/schema-version.json` | 用于在客户自有环境重建 |
| 4 | **审计记录** | `GET api/audit/logs` | 含操作人、时间、`CorrelationId` |
| 5 | **客户业务库数据** | 由客户自行导出 | **不在本系统范围**（本系统只读访问） |

### ⚠️ 现状缺口（须向客户如实说明）

| 缺口 | 影响 | 当前替代 |
|---|---|---|
| **无自助「租户数据导出」API** | 客户无法自行一键导出全量数据 | 走 DBA / 脚本通道（§2 #1#2） |
| **无「租户物理删除」API** | 删除需 DBA 手工执行 | 先 `disable` 停用，保留期内可恢复；删除由 DBA 执行并留痕 |
| Qdrant 快照为二进制 | 客户难以直接阅读 | 如需可读，另行导出 JSONL |

> 上列为 M14-07 交付的**已知能力边界**；若客户要求自助导出，应作为后续增强项评估（不在本项范围）。

### 2.1 按租户导出（推荐做法）

> 由 DBA 执行；**导出前先在只读副本或备份上操作**，避免影响在线库。

```sql
-- 示例：按 tenantId 导出关键表（具体表清单以实际库为准）
-- 使用 bcp / SELECT 导出为 CSV，逐表带上 TenantId 过滤条件
SELECT * FROM Users       WHERE TenantId = @tenantId;
SELECT * FROM AuditLogs   WHERE TenantId = @tenantId;
-- ... 其余业务语义/看板/应用表按同法
```

> 严禁在导出中夹带其它租户数据；导出物需加密存放。

## 4. 数据保留与删除

| 项 | 政策 |
|---|---|
| 停用后保留期 | 【待定稿，建议 ≥ 30 天，按合同/合规要求】 |
| 保留期内数据可用性 | 数据保留但不对外提供服务；如需恢复联系支持 |
| 保留期届满 | 执行物理删除（DBA） |
| 删除范围 | 元数据库中该租户记录 + 其向量数据（若租户独占集合） |
| 删除不可逆性 | **删除不可逆**；删除前须再次确认导出已完成 |
| 备份中的残留 | 备份文件按**自身保留期**自然淘汰；如需立即清除须单独处理备份介质 |
| 合规留痕 | 删除操作须审计（`POST api/audit/logs` 记录删除申请与执行） |

### 4.1 删除执行步骤

```
1) 书面确认：授权人签署《数据删除确认单》（含导出已完成声明）
2) 二次校验：确认导出物可读、完整（抽样）
3) 停用（若未停用）：PATCH api/tenant-management/{id}/disable
4) DBA 执行物理删除（SQL；按 tenantId 逐表删除或整库）
5) 删除向量数据（若为租户独占集合）
6) 记录删除结果 + 执行人 + 时间 + 关联单号（审计留痕）
```
