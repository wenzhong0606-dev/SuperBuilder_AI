## 0. 这份包是什么、给谁

让**非开发人员**能独立完成：安装 → 一次升级 → 日常运维 → 出故障时定位与上报 → 退出时导出数据。

受众分两层，每册标注适用对象：

| 标记 | 受众 | 关心什么 |
|---|---|---|
| **[运维]** | 客户 IT / SRE / 实施工程师 | 装什么、怎么起、怎么升级、怎么备份、怎么看健康 |
| **[管理]** | 客户系统管理员（业务侧） | 怎么开租户、配数据源、管用户权限、怎么看用量 |
| **[双方]** | 上述两类 | 故障怎么定级、找谁、数据怎么退出 |

## 2. ⚠️ 草稿性质与定稿条件（必读）

按 `M14.md` §M14-07 的依赖语义：**手册可在开发期起草，但必须在 M13-10/11/14 完成之后、G1 验收之前，依据实测结果完成定稿；G1 只接受可用交接包，不接受未经验证的草稿。**

因此本包中所有标注 **`【待实测回填】`** 的位置，必须由下列实测结果替换后才能定稿：

| 回填项 | 依赖 | 当前状态 |
|---|---|---|
| 服务目标（P95、错误率、可用性承诺） | PERF-01 / M13-12 | **受 OPEN「性能和恢复目标」阻塞** |
| RPO / RTO 数字 | DR-01 文档「目标值」列 + OPEN | 演练已闭环，**目标值待平台 owner 定稿** |
| 生产级告警阈值 | OPEN「性能和恢复目标」 | 出厂基线已就绪（见 §3 文档），生产值待定 |
| 支持环境清单（OS、单/双实例、数据源） | OPEN「支持环境」 | **待平台 owner 定稿** |
| 支持入口（邮箱/工单/电话） | 商务/客户成功 | **待填写** |
| 数据规模与硬件前提 | PERF-01 | **待实测** |

> 回填表单：`docs/plans/active/2026-09-open-decisions-form.md`（两项 OPEN 的待填表）。
> 纪律：**定稿前不得对外承诺任何数字**；草稿中的占位符一律不得被当作 SLA。
