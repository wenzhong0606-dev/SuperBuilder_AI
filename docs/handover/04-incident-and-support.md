## 1. 故障级别定义

| 级别 | 定义 | 典型场景 | 目标响应 | 目标恢复 |
|---|---|---|---|---|
| **P1 严重** | 全租户不可用，或数据错误/泄漏风险 | 应用无法启动；`/health` 长时间 `degraded`；跨租户数据可见；元数据库不可达 | 【待定稿，建议 ≤15 分钟】 | 【待定稿，建议 ≤4 小时】 |
| **P2 高** | 核心链路不可用，但有绕行 | 登录失败率骤升；Ask 全面失败（DB/LLM 异常）；数据源连接批量失败 | 【待定稿】 | 【待定稿】 |
| **P3 中** | 单功能异常或性能劣化 | 某个数据源扫描卡住；某看板渲染失败；P95 明显劣化；配额异常消耗 | 【待定稿】 | 【待定稿】 |
| **P4 低** | 咨询、易用性、优化建议 | 文案/翻译问题；操作疑问；功能请求 | 【待定稿】 | 按迭代排期 |

> ⚠️ 上表**响应/恢复目标为占位**，须与 `03-operations-runbook.md` §1 服务目标**同步定稿**，且**不得超过实测能力**（M14-07 验收判据 4）。

## 2. 处理责任划分

| 环节 | 客户运维 [运维] | 我方支持 | 我方研发 |
|---|---|---|---|
| 受理与分级 | 初判级别、收集信息（§4） | 复核分级 | — |
| 一线排查 | 巡检、查 `/health` `/metrics`、按关联 ID 拉日志 | 协助定位 | — |
| 应用缺陷 | 提供关联 ID + 日志 + 复现步骤 | 判定是否缺陷 | 修复与回归 |
| 环境/网络/DB | **负责**（宿主机、网络、SQL Server、Qdrant 运行） | 给指引 | — |
| 客户业务库 | **负责**（连接串、账号权限、库可用性） | 给指引 | — |
| 密钥保管 | **负责**（`Auth:SigningKey`、`SecretStore:MasterKey`） | 提供轮换流程（`03` §4） | — |
| 升级/回退执行 | **负责**（按 `01` §4） | 远程指导 | 缺陷修复 |
| 数据导出/退出 | 提出申请、提供授权记录 | 执行协调 | 提供通道（`06`） |

**边界原则**：客户自有环境（宿主、DB、网络、业务库、密钥）由客户负责；我方负责应用本身的缺陷修复与操作指引。

## 4. 报障与定位

### 4.1 报障必备信息（缺一将退回补充）

| # | 信息 | 获取方式 |
|---|---|---|
| 1 | **关联 ID（`X-Correlation-Id`）** | 出问题的那个响应头 |
| 2 | 发生时间（含时区） | — |
| 3 | 租户 / 账号 | 页面右上角 |
| 4 | 操作步骤与期望结果 | 文字或截图 |
| 5 | 错误码与提示文案 | 页面提示（形如 `SB_xxx`） |
| 6 | `/health` 输出 | `GET /health` |
| 7 | （若涉及指标）`/metrics` 相关片段 | 需 `platform:diagnostics:view` |

### 4.2 关联 ID 定位链路（验收判据 2 的演练脚本）

```
① 复现问题 → 从响应头取 X-Correlation-Id
② 在日志中按该值过滤，依次看：
     REQ  → 方法/路径/状态码/耗时/authTenant/effTenant/reqTenant
     RES  → 状态码与耗时
     异常 → UnifiedExceptionMiddleware 的结构化错误（错误码 + 关联 ID）
     审计 → AuditMiddleware（含 CorrelationId）
③ 判定：
     effTenant ≠ 预期租户        → 租户/权限问题（伪造参数已被拒）
     错误码 SB_AUTHZ_001/002     → 数据源或行级策略拒绝
     错误码 SB_BI_001~005        → 语义/问法问题，非故障
     错误码 SB_BI_006            → 业务库不可达
     错误码 SB_SERVICE_UNAVAILABLE → 平台未就绪（DB 不可达/未初始化）
```

## 5. 错误码速查（FAQ 核心）

| 错误码 | 提示 | 含义与处置 |
|---|---|---|
| `SB_UNAUTHORIZED` | 鉴权失败，请重新登录后再试 | 令牌无效/过期；重新登录。持续发生 → 查 `Auth:SigningKey` 是否被轮换 |
| `SB_FORBIDDEN` | 权限不足，当前账号无权执行该操作 | 角色权限点缺失；由管理员在 `api/identity/roles/{code}/permissions` 补 |
| `SB_AUTH_001` | 用户名或租户不存在，或账号已被禁用 | 核对租户编码与账号状态 |
| `SB_AUTHZ_001` | 当前账号无权访问所选数据源 | 数据源未授权；`POST api/data-source-access` 授权。**撤权即时生效** |
| `SB_AUTHZ_002` | 当前账号没有满足行级数据策略的访问范围 | 行级策略下的正常拒绝，非故障 |
| `SB_PFM_001` | 当前租户配额已用尽 | 调 `PUT api/quota/policy/{resourceType}` 或升级套餐 |
| `SB_PFM_002` | 操作越过了租户边界，已被安全策略拒绝 | **安全拦截**（曾用于伪装 `tenantId`）；确认是否有人伪造参数 |
| `SB_SECURITY_001` | 查询计划未通过最终安全校验，已在执行前阻断 | 查询被安全闸门拦截；属保护行为，记录并上报 |
| `SB_COST_001` | （成本/用量类限制） | 见提示文案与配额设置 |
| `SB_SERVICE_UNAVAILABLE` | 平台尚未就绪（数据库不可达或未完成初始化） | 查 `/health` 的 `state`/`reason`；元数据库连通性 |
| `SB_TOO_MANY_REQUESTS` | 请求过于频繁，请稍后再试 | 限流触发；核对 `RateLimit:*`；多实例需共享存储 |
| `SB_BI_001` | 未识别出可查询的数据表 | 换表述或指定业务对象 |
| `SB_BI_002` | 未识别出可分析字段 | 补充指标/维度。**业务库无对应域时属预期**（如无销售域问销售额） |
| `SB_BI_003` | 业务语义暂不支持该分析 | 调整问法或补语义 |
| `SB_BI_004` | 存在多个可能匹配的度量字段 | 明确指定（如「订单金额」而非「金额」） |
| `SB_BI_005` | 模型把握不足 | 补充指标/维度/筛选后重试 |
| `SB_BI_006` | 数据源暂时不可达 | 检查业务库连接与网络 |
| `SB_APP_*` | App 相关（未授权/未发布/查询受阻/幂等冲突等） | 见 `SB_APP_QUERY_BLOCKED`（查询被阻）、`SB_APP_DATASOURCE_UNAUTHORIZED`（数据源未授权）、`SB_APP_NOT_PUBLISHED`（未发布） |
| `SB_AGENT_001` | 智能体未返回有效内容 | 重新描述任务 |

## 6. 常见故障 FAQ

| # | 现象 | 可能原因 | 处置 |
|---|---|---|---|
| 1 | 应用起不来 | `Auth:SigningKey` 缺失或不合规 | 报错信息直接指明：缺失 / 用了历史默认值 / 字节数不足 / 不同字符不足。按 `01` §2.1 配置 |
| 2 | `/health` = `degraded`，`state=MigrationsPending` | 库落后于代码 | 执行 `01` §4 升级 |
| 3 | `/health` = `degraded`，`state=SeedIncomplete` | 种子某步失败 | 读 `reason`；修复后重启自动补齐（种子幂等） |
| 4 | 登录成功但看不到菜单 | 角色权限点缺失 | 核对角色权限 |
| 5 | 语言切换器不出现 | 租户只有 1 种语言 | 见 `02` §3 限制 1 |
| 6 | Ask 一直答「无法识别表/字段」 | 业务库无对应域，或语义未确认 | 先确认实体/指标；无该域属预期（`SB_BI_002`） |
| 7 | 数据源测试连接失败 | 网络/凭据/权限/驱动 | 用 `test-connection` 的具体原因逐项排查 |
| 8 | 扫描一直不完成 | 业务库锁、后台服务异常、积压 | 查 `scanBacklog.pending` 与 `MetadataScanJobs` 状态 |
| 9 | 改权限后旧会话仍能操作 | —（已修复） | 权限/组变更会**立即轮换安全戳**，旧令牌失效；若仍可操作，按 §4 报障 |
| 10 | 双实例下行为不一致 | 限流/缓存在进程内 | 见 `03` §4「多实例部署注意」 |
| 11 | 加密连接串解不开 | `SecretStore:MasterKey` 变更或丢失 | 见 `03` §4 密钥轮换（**不可直接轮换**） |
