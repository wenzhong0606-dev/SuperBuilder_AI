# SuperBuilder AI 平台产品与开发要求

> 本文档汇总当前阶段已确认的产品目标、业务流程、权限边界、交互规范和验收要求，作为后续设计、开发、测试及评审的统一参考。

## 1. 产品定位

SuperBuilder AI 应建设为一个支持平台治理、多租户隔离、多语言、数据源管理、元数据管理和智能问数的企业级平台。

系统需要同时服务三类管理范围：

1. 平台级：平台管理员管理全局能力、租户、平台语言和平台默认资源。
2. 租户级：租户管理员管理本租户用户、数据源、元数据、语言覆盖及业务配置。
3. 用户级：普通用户在授权范围内使用数据源、智能问数及其他业务功能，并保存个人偏好。

所有功能应形成可实际操作的完整闭环，不能只提供数据库结构、静态展示或无后续页面的跳转入口。

## 2. 核心业务闭环

平台的标准初始化与使用流程如下：

1. 系统首次启动时检测是否存在平台管理员。
2. 如果不存在平台管理员，登录页应显示一次性平台管理员初始化界面。
3. 不应仅抛出“请配置环境变量”的异常来中断启动或登录。
4. 第一个平台管理员创建完成后，一次性初始化入口自动关闭。
5. 平台管理员登录后创建租户及该租户的首位租户管理员。
6. 也可以在后续阶段扩展为租户自行注册，但注册结果仍需符合平台治理规则。
7. 租户管理员登录后创建数据源、配置访问授权并扫描元数据。
8. 租户用户只能看到自己被授权的数据源。
9. 用户进入 Ask 页面后，可以从下拉框选择已授权的数据源并进行问数。

不得出现以下断链情况：

- 登录成功后进入 Ask 页面又被重定向回登录页。
- 用户已登录但权限、令牌或会话状态未正确恢复。
- Ask 页面数据源下拉框为空，但管理端明明已经创建并授权数据源。
- 菜单中存在入口，但目标页面没有实际数据或无法完成操作。

## 3. 平台管理员

### 3.1 初始化

- 初始化时必须能够创建第一个平台管理员。
- 初始化页面应提供用户名、显示名、邮箱和安全口令等必要字段。
- 口令至少 8 位，并给出清晰的前端校验提示。
- 初始化接口只能在安全范围内使用，例如限制本机调用并在首位管理员创建后关闭。

### 3.2 存储与数量

- 平台管理员信息存储在系统身份用户、角色、用户角色及相关权限数据中。
- 平台应支持添加多个平台管理员。
- 平台管理员不应依赖单一环境变量账号长期运行。
- 平台管理员应使用正式的身份认证、密码哈希、角色和权限机制。

### 3.3 租户管理范围

- 默认平台管理员可以管理全部租户。
- 系统设计应支持后续扩展为不同平台管理员管理不同租户范围。
- 如果启用分范围治理，必须通过明确的管理员—租户授权关系实现，不能仅依赖前端隐藏菜单。
- 所有平台级租户操作均应进行服务端权限校验和审计记录。

## 4. 租户管理

### 4.1 租户创建

平台管理员创建租户时，应在同一事务内完成：

- 创建租户。
- 创建首位租户管理员。
- 设置管理员初始口令。
- 初始化租户默认配置。
- 设置租户支持的语言。
- 设置租户默认语言。

任一步骤失败时应整体回滚，避免产生没有管理员的孤立租户。

### 4.2 租户页面

租户页面应具有现代感、科技感，并与全平台视觉风格一致。

页面应包括：

- 租户总数、已启用、已停用等概览信息。
- 默认显示租户列表。
- 支持搜索租户编码和名称。
- 支持创建、启用、停用和设置操作。
- 启用与停用操作需要二次确认。
- 创建租户使用清晰的弹窗或分步表单，不应长期占据列表页面主体。
- 语言选择应使用直观的语言卡片，不使用写死的固定选项。

## 5. 多语言体系

### 5.1 分层模型

多语言体系必须包含以下三个层级：

1. 平台语言目录：平台维护系统支持哪些语言。
2. 平台文本基线：每种语言对应一套完整的系统文本。
3. 租户文本覆盖：租户继承平台文本，只保存需要个性化的差异项。

例如：

- 平台中文文本：`Document.OutboundOrder = 出库单`
- 租户 A 继承后可覆盖为：`Document.OutboundOrder = 出库凭证`
- 租户 A 删除覆盖后，应自动恢复为平台的“出库单”。

### 5.2 平台语言维护

多语言页面应支持平台管理员：

- 查看语言目录。
- 添加新的语言区域，例如 `en-US`、`zh-CN`、`ja-JP`。
- 维护语言显示名称、本地名称、启用状态和排序。
- 新增语言时可从已有语言复制文本键集合，形成待翻译的初始资源。
- 为每种语言维护系统所需的全部文本。

系统文本至少应涵盖：

- 登录、退出、确认、取消、保存、关闭等通用文本。
- 菜单、页面标题、按钮、表单标签、提示和错误信息。
- 业务对象或业务术语，例如出库单。

语言选项必须来自数据库维护的语言目录，不得在租户页面写死中文和英文。

### 5.3 租户语言配置

- 平台管理员创建租户时，可以从平台已启用的语言中选择该租户支持的语言。
- 必须至少选择一种语言。
- 必须从已选语言中指定租户默认语言。
- 例如租户 A 支持中文和英文，默认英文，则该租户用户首次登录应显示英文。

### 5.4 租户专属文本

- 租户进入多语言页面时，默认看到平台维护的文本。
- 页面应同时显示平台默认值和租户最终显示值。
- 租户管理员可以维护本租户专属文本。
- 页面应清楚标识“平台基线”“已继承”和“租户专属”。
- 租户覆盖应支持一键恢复继承。
- 平台基线发生变化后，未覆盖该键的租户应自动继承最新值。

### 5.5 用户语言偏好

- 用户只能在当前租户启用的语言范围内切换。
- 用户首次登录采用租户默认语言。
- 用户主动切换语言后，应按“租户 + 用户”缓存其偏好。
- 下次登录时优先恢复用户上次选择。
- 如果原语言被租户停用，则自动回退到租户默认语言。
- 登录或切换语言时，应加载“平台文本基线 + 租户覆盖”的最终资源。

## 6. 登录、会话与端口

- Web 项目实际运行端口为 5080 和 5081 时，各端配置必须与真实 HTTP/HTTPS 地址一致。
- API 基础地址不应因错误端口或协议导致 SSL 连接异常。
- HTTP 请求重定向时不得丢失 Authorization 请求头。
- 登录成功后必须正确持久化令牌、用户信息、租户信息、权限和语言配置。
- 页面刷新后应能够恢复会话并通过服务端校验。
- 认证失败、网络失败和权限不足应使用用户可理解的错误提示。

## 7. 菜单与布局

- 平台管理员应看到平台治理相关菜单，包括租户管理和平台多语言维护。
- 租户管理员应看到本租户数据源、元数据、用户及租户语言覆盖等菜单。
- 普通用户只能看到有权限访问的功能。
- 菜单不得显示成两列。
- 菜单区域内容超出高度时应使用纵向滚动条。
- 所有菜单权限必须以后端权限为最终依据，前端显示控制只用于改善体验。

## 8. 数据源管理

### 8.1 页面交互

- 数据源管理页面默认显示当前租户的数据源列表。
- 数据库类型、连接字符串和新增表单仅在用户点击“新增数据源”后显示。
- 页面应展示数据源名称、数据库类型、启用状态、元数据表数量和字段数量。
- 表格默认宽度为 100%。
- 内容超过容器宽度时显示横向滚动条，不能压缩成不可读的多列布局。

### 8.2 创建与授权

- 租户管理员可以创建数据源。
- 数据源必须归属当前租户。
- 创建数据源后，系统应为创建者写入明确的访问授权。
- 后续应支持按用户或角色授权数据源。
- Ask 页面只返回当前用户被授权且已启用的数据源。

### 8.3 元数据展示

- 数据源详情页必须显示当前租户绑定的数据源信息。
- 必须显示该数据源扫描得到的 MetadataTable、MetadataColumn 和 MetadataSemantic 数据。
- 数据为空时应提供明确空状态和下一步操作提示。

## 9. 元数据关系与详情页面

这里所说的“外键关系”主要指平台系统内部元数据实体之间的关联，不是业务数据库自身的外键关系。

重点关系包括：

- `MetadataTable → MetadataColumn`
- `MetadataColumn → MetadataSemantic`
- `MetadataColumn → Vector/Qdrant Point`
- `MetadataSemantic → Vector/Qdrant Point`

### 9.1 列表展示

- MetadataTable 应显示真实主键 ID、表名、注释、业务域和字段数量。
- MetadataColumn 应显示真实 ID、所属 MetadataTable ID、字段名、注释、数据类型、长度、主键、可空、业务键及 VectorId。
- MetadataSemantic 应显示真实 ID、MetadataColumnId、业务含义、关键词、同义词、示例问题、业务域、置信度、来源、向量模型和向量维度。
- Vector 项应显示 VectorId、所有者类型、所有者 ID、模型、维度和搜索文本。

### 9.2 交互要求

- `true/false` 字段应以只读开关或状态组件展示，不直接显示原始文本。
- 主键、数据类型、状态和来源应使用统一标签样式。
- 外键或关联 ID 应是可点击链接。
- 链接必须进入具有实际数据的详情页面，不能只跳到无内容页面或无效锚点。
- 元数据列、语义和向量均应有独立详情路由。
- 详情页应展示当前实体数据及其上下游关系。
- 所有详情查询必须校验当前租户和元数据查看权限，防止跨租户读取。

## 10. Ask 页面

- Ask 页面数据源下拉框必须列出当前用户有权访问的数据源。
- 如果没有数据源，应显示“尚未配置或授权数据源”的明确提示。
- 不应将“无数据源”误报为系统错误。
- 用户未登录或令牌失效时才跳转登录页面。
- 已登录但缺少权限时应显示无权限状态，不应形成登录跳转循环。

## 11. 视觉与交互规范

### 11.1 整体风格

- 整个平台采用统一的现代感、科技感设计语言。
- 页面之间的颜色、圆角、阴影、间距、图标、按钮和状态组件应保持一致。
- 避免局部页面仍使用浏览器默认控件或与系统主题不一致的 Bootstrap 默认蓝色。

### 11.2 主题颜色

- `btn-primary`、`badge-primary` 及其他 `*-primary` 组件必须使用系统主题主色变量。
- hover、active、focus 和 disabled 状态均应符合主题。
- 主按钮应具有适度的科技感渐变、光感或阴影，但不能影响可读性。

### 11.3 页面布局

- 列表优先，新增或编辑内容按需展开。
- 大型配置使用弹窗、抽屉、标签页或独立详情页。
- 表格宽度默认 100%，统一放入可横向滚动的容器。
- 空状态、加载状态、错误状态和重试入口必须统一。
- 桌面端和窄屏下均应保持可用，复杂网格在窄屏下自动变为单列。

## 12. 权限与数据隔离

- 平台级操作必须校验平台权限。
- 租户级维护必须校验租户管理员或对应细粒度权限。
- 数据源和元数据查询必须限定当前租户。
- 用户数据源列表必须同时满足租户归属、启用状态和显式授权。
- 不能依赖前端传入 TenantId 作为唯一隔离依据。
- 平台管理员代表平台管理某租户时，应记录明确的管理目标和操作行为。
- 重要操作应写入审计日志。

## 13. 数据与事务要求

- 租户及首位管理员创建必须使用事务。
- 数据源及创建者授权应保持一致性。
- 平台文本与租户覆盖使用唯一键约束，避免同一租户、语言和文本键出现重复记录。
- 平台共享数据使用明确的平台作用域，租户覆盖使用明确 TenantId。
- 删除租户覆盖不得删除平台基线。
- VectorId 对应外部向量存储标识，详情页应说明其所有者关系，不应伪装为关系数据库实体外键。

## 14. 错误处理与用户提示

- 后端异常不能直接以技术堆栈暴露给普通用户。
- 表单校验应尽量在前端即时完成，后端仍需重复校验。
- 冲突、未授权、禁止访问、找不到数据和网络失败应使用不同提示。
- 所有失败操作应保留用户已输入内容，避免要求重新填写完整表单。
- 成功创建、保存、启用、停用、恢复继承和扫描元数据后应提供清晰反馈。

## 15. 测试与验收

每次相关改动至少应验证：

1. 后端项目编译通过。
2. Web/Components 项目编译通过。
3. 完整自动化测试通过。
4. 数据库迁移可成功生成和应用。
5. 首次平台管理员初始化闭环可用。
6. 平台管理员创建租户和首位管理员可用。
7. 租户语言选择来自平台数据库语言目录。
8. 租户默认语言和用户语言缓存行为正确。
9. 平台文本继承、租户覆盖和恢复继承行为正确。
10. 数据源创建、授权、列表和 Ask 下拉框行为一致。
11. MetadataColumn、MetadataSemantic 和 Vector 关系跳转均有真实详情数据。
12. 所有相关查询均通过租户隔离和权限测试。
13. 页面在常见桌面宽度和窄屏下没有双列菜单、内容溢出或无法操作的问题。

## 16. 后续开发原则

- 新功能首先确认属于平台级、租户级还是用户级。
- 新页面必须同时考虑权限、租户隔离、多语言、主题和响应式布局。
- 新增用户可见文本必须进入统一文本资源，不应继续散落硬编码。
- 新增实体关系链接时，必须同步提供可查询的详情接口和详情页面。
- 新增列表页默认先展示数据，创建表单按需出现。
- 所有实现以完整业务闭环为目标，不以“接口存在”或“页面能打开”作为完成标准。

## 17. G1 支持环境边界（2026-09-14 O1 回填）

企业 Web 试点首批准入的数据源与运行边界（与 `release-evidence.md`「O1 回填」一致）：

| 维度 | 边界 |
|---|---|
| 支持的业务数据源类型 | **MySQL**（连接→扫描→查询三层完整实现并验证）；SQL Server / PostgreSQL 仅连接分支存在，业务库元数据扫描未实现，**不纳入 G1 验收** |
| 已验证层级 | MySQL 三层已验证（WMS `steccn_wms` 真实库）；SQL Server / PostgreSQL 未做业务库扫描验证 |
| 浏览器 | Chromium 内核（Chrome / Edge 最新两大版本）；其余内核首批不认证 |
| 语言 | 首批 zh-CN；多语言界面需显式配置，不在 G1 验收 |
| 部署 | Windows Server 2022 x64、直接安装、单实例（拓扑不要求 API/Web 同进程，不要求 SQL Server/Qdrant 同机） |

> SQL Server / PostgreSQL 业务库扫描能力若客户需要，列为 G1 后增强项，不得写入当前 G1 对外承诺。
