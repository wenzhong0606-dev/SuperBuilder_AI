## 3. 执行前提与沙箱边界（诚实标注）

| 项 | 现状 | 影响 |
|---|---|---|
| 测试库规模 | 用户已在真实环境**多绑数据源（已绑定未扫描）**；沙箱 Qdrant 仍 1061 旧值 | 规模待扫描后统计；达标则直接 PERF，不足则差额合成 |
| 压测脚手架 | 无 Perf/Benchmark 工程（Glob 验证） | 需新建负载器 |

| LLM 调用 | Ask 依赖 Qwen，沙箱有 `HTTP_PROXY` 限制 | 实测 Ask P95 受网络/模型抖动影响，需真实调用 |
| Qdrant | 本地可用（6333/6334） | 向量灌入与查询可达 |
| 元库 | `localhost/SuperBuilder_Platform` 可达 | 合成元数据可写入 |

## 4. 数据准备方案（T1 · 前置 blocker）

**策略：真实数据源扫描优先，差额合成补足**（用户已多绑数据源，已绑定未扫描）

1. **执行元数据扫描**：对你绑定的数据源触发扫描（后端 `POST /api/data-sources/{id}/metadata/scan`），落库元库 `MetadataTables`/`MetadataColumns` + 向量灌 Qdrant `superbi_metadata`。*执行环境待定（见下方提问）。*
2. **统计真实规模**：扫描后查元库表定义数 + Qdrant `points_count`，与 O2 目标（≤1000 表 / ≤50000 向量）对比。
3. **差额补足**：若真实规模 < 目标，按缺额生成合成表/向量补齐到上限（复用扫描落库结构 + 1024 维 upsert）。
4. **验证链路**：在目标规模下跑一次"扫描→实体确认→Ask/查询"，确认不崩。
5. *不再默认纯合成*：真实绑定已存在，优先用真实元数据，合成仅补差额。

**执行环境决策（T1 启动前必定）**：扫描需运行态后端 + 数据源可达。你的绑定在真实环境、沙箱未同步，故 T1 须在「沙箱可达的数据源」或「真实环境」择一执行。

## 5. 负载工具（T2 · 真实环境执行）

- **选型**：轻量 Python 脚本 `scripts/perf/load_test.py`（依赖 `requests`），直接打真实环境 API，**不依赖构建测试工程**（真实部署无测试工程、沙箱构建受限）。
- **采集**：P50/P95/P99、失败率、吞吐(RPS)、每请求 token 成本（按 Qwen 计费另计）；内存/CPU 走真实服务器 `ObservabilityMiddleware` + 系统监控。
- **运行**：`python load_test.py --base-url <真实API> --token <获取> --scenario ask|query|login --concurrency 1,5,10,20 --requests N`。端点路径见脚本顶部常量，按真实环境调整。

## 6. 场景定义（T3）

| 场景 | 端点/动作 | 目标 P95 | 并发梯度 |
|---|---|---|---|
| Ask 问答 | `POST /api/ask` 自然语言问句 | ≤ 8 s | 1/5/10/20 |
| 实时查询 | 查询计划执行接口 | ≤ 2 s | 1/5/10/20 |
| 登录/鉴权 | `POST /api/auth/login` | 基线 | 1/5/10/20 |

查询分布：从**真实扫描后的元数据**抽样问句（库存/入库类，匹配 O3 试点口径；若补了合成差额则含合成表问句）。

## 7. 指标采集与判据表（T4）

逐场景记录并与 §1 对照，任一指标超目标即标记不达标，回 §1 调目标或进优化。

## 8. 超载恢复验证（T4）

- 注入并发 > 20（如 50/100），确认：**超限返回 429**、无 OOM、租户隔离不破、积压有界（≤ 阈值触发拒绝）。
- 恢复后登录/Ask/查询可用，数据一致。

## 9. 执行顺序（真实环境）

```
T1 数据扫描（真实环境触发）→ T2 负载脚本就位 → T3 场景确认 → T4 实测+超载（真实环境）→ T5 验收报告（用户贴数据，AI 出稿）
```

### 真实环境执行清单
1. 对你绑定的数据源在真实平台触发元数据扫描（或确认已扫）。
2. 统计真实规模：元库表定义数 + Qdrant `points_count`（目标 ≤1000 表 / ≤50000 向量；不足则按缺额合成补齐到目标）。
3. 在真实服务器部署 `scripts/perf/load_test.py`，`pip install requests`。
4. 获取 API token（按你真实鉴权），运行负载脚本，并发梯度 1→5→10→20，逐场景（ask/query/login）。
5. 注入超载（并发 50/100）验证 429 + 不 OOM + 租户隔离。
6. 采集内存/CPU（真实服务器 `ObservabilityMiddleware` + 系统监控）。
7. 填 `docs/ops/perf-01-report.md`，贴给 AI 出最终验收报告。

## 10. 风险与未决

- **数据规模真实性**：真实绑定元数据优先；若真实 < 目标须补合成差额，结论标注"含合成补足"。
- **LLM 抖动**：Ask P95 受模型端影响，多次采样取稳定值。
- **端点路径**：脚本默认占位端点，须按你真实环境 API 调整（见脚本注释）。
- **已决**：T1 = 真实扫描优先；负载工具 = 轻量 Python 脚本（非测试工程）；执行环境 = 真实环境。
