# 2026-09-09 工作日志

## F5 卡在"正在恢复登录会话…" 根因与修复（M8-05 会话自举反模式）
- 现象：登录后打开 /ask 正常；F5 刷新后一直显示"正在恢复登录会话…"（Ask.razor:16 `@if(!State.SessionRestored)` 守卫）。
- 根因：`MainLayout.OnAfterRenderAsync`(与 `BlankLayout`) 在 `ServerPrerendered` 下，于 `OnAfterRenderAsync(firstRender)` 中做「本地还原 + 网络校验」。原代码把 `StateHasChanged()` 放在**整段异步末尾**：先 `RestoreAsync`→`ValidateAsync`(GET /api/auth/me)→`L10n.InitializeAsync`(多网络调用)，最后才重渲染。
  - 登录流程里首屏未登录，`if(IsAuthenticated)` 块被跳过，`ValidateAsync`/`L10n.InitializeAsync` **从未真正跑过**；F5 后才首次带令牌执行它们。
  - `GetJsonAsync` 不抛异常（异常被吞），但 `L10n.InitializeAsync` 内部 `LoadRuntimeTextsAsync` 等网络调用未包 try/catch 且 HttpClient 无短超时；任一挂起/抛错 → `OnAfterRenderAsync` 无法完成 → `StateHasChanged` 永不到达 → 页面永久停在预渲染"恢复中"态。
- 修复：本地 `RestoreAsync` 完成后**立即 `StateHasChanged()`** 脱离恢复态；`ValidateAsync`/`L10n.InitializeAsync` 包 try/catch（网络异常不登出、不撕裂 SignalR 电路）；主题 `JS.InvokeAsync("SuperBuilder.getTheme")` 也包 try/catch。
- 改动文件：`SuperBuilder_AI.Components/Components/Layout/MainLayout.razor`、`BlankLayout.razor`。RCL 编译 0 error（仅 IL2026 裁剪警告，既有）。
- 验证：RCL build 通过；用户需本机 F5 复测 /ask 是否立即进入（不再卡恢复中）。
- 关联记忆：M8-05 "SignalR 预渲染无 JS→主题移到 OnAfterRenderAsync(firstRender)"；AppState.SessionRestored 由 AuthStore.RestoreAsync 的 finally 置位。

## F5 不显示（续）：二次修复 + 诊断
- 用户复测仍"刷新不显示、菜单导航正常"。关键事实：_Host.cshtml 用 `render-mode="Server"`（**非** ServerPrerendered），故 F5 首帧由电路接管后渲染，无预渲染 NRE；Routes.razor 原无 ErrorBoundary，首帧异常会整页空白。

- 仍存两处真实隐患并修复：
  1. `AppState.ClearSession()` 原把 `SessionRestored` 复位 false；F5 后 `ValidateAsync` 遇 401→`ClearAsync`→`ClearSession` 会让 Ask 退回"恢复中"且永不恢复（OnAfterRenderAsync(firstRender) 已消费）。改为不复位 SessionRestored（仅 IsAuthenticated 驱动登录态）。
  2. `Routes.razor` 加 `<ErrorBoundary>` 包裹 RouteView，首帧渲染异常可见（红字报错）而非空白，便于定位。
- 仍"不行"的两大可能：(A) 运行实例未含改动（需重建 RCL+Web）；(B) F5 首帧有隐藏异常（现由 ErrorBoundary 暴露）。

- 结论：代码侧已让"恢复中"不再卡死（StateHasChanged 提前 + ClearSession 不复位）；若仍空白，需上述四项实证定位真实异常/令牌来源。
