## PowerShell 5.1 工程坑（已固化，避免重犯）
1. 原生命令 stderr（如 NuGet 告警）在 `$ErrorActionPreference='Stop'` 下被误判为终止性错误 → 调用原生命令处临时降级 `Continue`。
2. `Write-Host` 走 host 流，**PS5.1 无法被赋值/重定向捕获** → 校验类脚本改 `Write-Output`（利于 CI 捕获）。
3. 重复 BOM 编码会**叠加 BOM**（`utf-8` 读不剥 BOM + `utf-8-sig` 写又加）→ 使 `<#` 不在首位、帮助块失效并引发级联解析错误。修法：读用 `utf-8-sig` 且 `lstrip('\ufeff')`，写用 `utf-8-sig`。
4. 执行脚本被策略拦 → 用 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force`（仅进程级，不改机器策略）。
5. curl on Windows：`-o /c/...` 绝对路径会被当字面量导致 0 字节，须用**相对路径**。

## 🔴 追加发现（续）：硬加载深层路由会「清掉有效会话」+ API 观测盲区
> 排查「是否还有同形态会话时序缺陷」时，用 Playwright 逐路由**独立登录**硬加载实测得来的。

### 证据 1：9 条深层路由中 2 条被登出
- ✅ 正常：`/ask` `/apps` `/dashboards` `/data-sources` `/semantic-labels` `/model-accounts` `/admin/tenants`
- ❌ **落到 `/login`（登出）**：`/agent`、`/business-model`

### 证据 2：根因链（两条缺陷叠加）
1. 页面自身 `OnAfterRenderAsync(firstRender)` 早于 `MainLayout` 异步 `RestoreAsync` → 此时 `AppState.Token` 为空 → `ApiClientBase.CreateClient()` **不带 Bearer** → 401。`Agent.razor` 还会把 `State.TenantId` 塞进查询串（`api/agent/plans?tenantId=0`）。
2. `ApiClientBase.OnUnauthorized()` 判据是 `if (!AppState.IsAuthenticated) return;`。401 **异步返回**，若期间自举已完成（`IsAuthenticated=true`）→ 该 401 被当成真实过期 → `ClearSession()` + `NotifySessionExpired()` → `MainLayout` `Session.ClearAsync()`（**清 localStorage**）+ `NavigateTo("/login")`。
→ **一个"无令牌请求"的 401 杀死了刚还原成功的有效会话**（竞态，非确定性；未复现的页面只是跑赢了竞态）。

### 证据 3：API 观测盲区（取证陷阱，务必记住）
`Program.cs` 中间件顺序：`AuthMiddleware(599)` → `RateLimitMiddleware(600)` → `UseAuthorization(601)` → **`ObservabilityMiddleware(603)`**。
→ **401/403/429 在观测中间件之前短路，日志完全看不到**。
实证：`curl /api/agent/plans?tenantId=0` → **401**；`curl /api/agent/tools` → **401**；RES 行数 **143 → 143（新增 0）**。
> ⚠️ **本项目 API 日志不能作为「无鉴权失败」的证据**。判定 401/403/429 必须直接复现或先调整中间件顺序。
