## 向量阶段卡住根因定位 + 修复（2026-09-14 续）
- 用 `scripts/scan_diag.py`（无浏览器 HttpClient 诊断脚本，`--trigger` 触发 / `--job-id` 监控，轮询 job 进度、检测卡住与 API 不可达）对数据源 #5 实跑复现：
  - 进度 `vec=0→77→336→397→451→586` 后冻结于 `586/935 pct=87%`；`API不可达累计=0.0s` → **排除 API 崩溃**，定位为「向量阶段内部 Qwen embedding 请求挂起/超时且不重试、无取消令牌透传」。
  - 与上次 295/1230（API 进程崩溃 502）是**两类不同故障**。
- 根因 4 点：① `MetadataScannerService`→`MetadataVectorService`→`QwenEmbeddingService`/`QdrantService` 整链无 `CancellationToken`；② `QwenEmbeddingService` 仅重试 429/5xx，单请求超时（`OperationCanceledException`）不重试→被吞请求永久挂起；③ `QdrantService.Upsert*` 无 deadline；④ 进度只计成功表，失败表 `VectorsProcessed` 不推进→进度假冻结。
- 修复（已落盘，待推 CI）：① 接口 `IEmbeddingService`/`IMetadataVectorService`/`IQdrantService` 的 `GenerateAsync/IndexAsync/UpsertAsync/UpsertBatchAsync` 加 `CancellationToken ct = default`；② `MetadataVectorService.IndexAsync(metadataTable, ct)` + `MetadataScannerService` 两处 `IndexAsync(table, ct)` 透传；③ `QwenEmbeddingService` 全量 `ct` 透传 + 重试循环内捕获 `OperationCanceledException when(!ct.IsCancellationRequested)` 纳入指数退避重试；④ `QdrantService` 两处 `Upsert` 传 `cancellationToken: ct`；⑤ `EmbeddingOptions.TimeoutSeconds` 120→45；⑥ 扫描器对失败表按 `ExpectedVectorCount` 计入 `VectorsProcessed`。`FakeEmbeddingService`/`FakeEmbedding`/`FakeQdrant`/`FakeVector` 同步加 `ct` 匹配接口签名。
- 链路已闭环：`MetadataScanHostedService` 以 `ct: stoppingToken` 透传至 `ScanAsync` → 故 host 关闭/任务取消可中断在途 embedding；**job 级取消（用户中止扫描）尚未接 `CancellationToken` 源，超出本次范围**。
- 验证限制：沙箱 `dotnet build` 仍因 NuGet `SHGetKnownFolderPath` 根因失败，无法本地编译；依赖 CI（runner 干净 Windows）全量回归（单测 + Golden 契约 + E2E）验证编译/契约。
