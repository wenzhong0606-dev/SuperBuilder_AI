### 关键语义（易错）

- 保底分支**在硬安全门之后、语义证据门之前**：优先级 = 硬错误(→Low) > 保底(→Medium/High) > 无语义证据(禁 High) > 阈值。
- 「与表纠正同待遇」= **只抬下限、不封顶**：`score >= 0.80` 时返回 High，否则 Medium。所以断言必须是 `>= Medium`（与既有表纠正用例一致），写死 `== Medium` 会在高分行上失败。
- 与 `TableCorrectionHonored` 的区别：后者靠问题文本里的锁表句式反推；`LearningApplied` 由调用方**显式传入**，因此能覆盖值映射/外键/列展示类规则（这些从文本推不出来），这正是 Phase 4 存在的理由。

### 踩坑：置信度测试里「基线不是 Low」

`CalculateConfidenceScore` 是**按可用证据加权归一化**（`weightedScore / availableWeight`）。
用 `EmptyMetadataSemanticSearchService` 时只有 Validation(1.0,w=0.10) + RepairStability(1.0,w=0.05) 可用，
归一化后得分恒 ≈ 1.0 → 再经「无语义证据禁 High」门 → **基线恒为 Medium，永远到不了 Low**，
于是「保底到 Medium」这个断言变成空转（还反过来暴露了 `== Medium` 的写法错误）。

**正确造基线的方法**：让语义替身返回一条**低分**向量命中（`VectorType="semantic"`, `Score=0.20`,
`Table`/`Column` 均 null），则可用权重 = Semantic(0.20)+Validation(0.10)+RepairStability(0.05)，
得分 = (0.20×0.20+1.0×0.10+1.0×0.05)/0.35 ≈ **0.543 < 0.60 → 基线 Low**，保底效果才可观察。
