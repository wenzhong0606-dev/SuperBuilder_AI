## 3. D14 Regression Forensic Audit 结论

本轮不得根据 FAIL 数量直接修改业务逻辑。根因必须按责任层分类：

```text
Semantic Resolution
QueryPlan Binding
QueryShape Evaluation
Confidence / Decision Gate
Runtime / SQL
```

已经确认：

1. GQ-011 的失败点是 `QueryPlanQueryShapeScoringService` 对 Metric Order 使用 `Golden MetricSemanticText` 与 Runtime `QueryOrder.MetricName` 比较，而 Runtime Plan 在此前使用了物理 `OrderBy` token（如 `quantity`），形成语义 Contract 不一致。
2. `QueryOrder` 本身同时保存 `MetadataColumnId + Field + IsMetric + MetricName + Aggregation`，因此不应修改 Model，而应修正 Plan Binding。
3. 本次修复只在 `QueryPlanBuilder.SemanticResolution` 的 Runtime Order 构造处处理：`MetricName` 使用对应 Metric 的 `SemanticText/Name`，`Field` 仍由 Order Resolution 写入物理字段。
4. 不修改 `DimensionResolutionEvidenceService`、Ambiguity Gate、DirectKey/MasterJoin Contract、Golden Expected、Release Gate。
5. GQ-002/GQ-008 的 Ambiguous 安全行为不得为了提高 Positive PASS 率而放宽。
6. GQ-005/GQ-009 必须根据实际 Metadata Snapshot 判断：存在稳定 Master 才 Join；不存在则 DirectKey；没有稳定 Key/展示证据才 BLOCK。
7. GQ-007 Multi-Metric 必须独立审计每一个 Metric Resolution，禁止通过降低统一 Semantic Gate 制造 PASS。

## 4. 多数据库正式业务 Contract

系统支持多数据库，JOIN 不是默认行为：

```text
Dimension
   ↓
当前 Metadata Snapshot
   ↓
存在稳定 Master Table / Master Evidence？
   ├─ YES → 同 DataSource → MasterJoin → QueryPlan.Joins
   └─ NO  → Fact Association / Dimension Key
              ↓
            DirectKey
              ↓
            不生成 JOIN
```

跨 DataSource Master 不得伪装成 Runtime Executable JOIN；必须保持不可执行/安全阻断状态。

因此 Golden Case 中出现“供应商/物料”并不意味着生产代码必须存在对应主表；测试必须服从真实 Metadata Contract。
